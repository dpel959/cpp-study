# C++ STL & Algorithm Study

C++17의 표준 라이브러리와 기본 알고리즘을 직접 사용하고 구현하면서, **컨테이너와 알고리즘이 내부에서 어떻게 동작하는지**를 학습한 프로젝트입니다.

완성된 하나의 프로그램보다는 함수 포인터, 함수 객체, 컨테이너, 탐색, 정렬, 동적 계획법을 주제별 예제로 남긴 기록입니다. 학습 중 생긴 질문과 실수하기 쉬운 지점을 코드 주석에 함께 정리했습니다.

## 프로젝트 목표

- STL 컨테이너와 알고리즘의 사용법뿐 아니라 동작 비용 이해
- 반복자 무효화, 경계값, 소유권처럼 오류가 발생하기 쉬운 조건 확인
- 기본 정렬 알고리즘을 직접 구현해 시간·공간 복잡도 비교
- 함수 포인터, Functor, 람다 등 호출 가능한 객체의 차이 이해
- 구현 과정에서 발견한 문제와 판단 근거를 주석으로 기록

## 강의 기반과 차별화

강의에서 학습한 STL과 알고리즘 예제를 출발점으로 삼았습니다. 예제를 그대로 재현하는 데서 끝내지 않고, 경계 조건과 메모리 사용을 다시 검토해 다음 부분을 직접 변경하거나 추가했습니다.

- `priority_queue` 사용 예제와 별도로 벡터 자체를 힙으로 만드는 HeapSort 구현
- 병합 단계마다 벡터를 생성하지 않고 임시 버퍼 하나를 모든 재귀 호출에서 재사용
- 중복값이 많은 QuickSort에서 한쪽 분할과 무한 반복을 줄이는 조건 적용
- 빈 벡터의 `size() - 1` 언더플로우를 막고 덧셈 오버플로우 위험을 낮춘 이진 탐색
- `vector::erase` 이후 무효화된 반복자를 다시 사용하지 않는 순회 구조 적용
- 설명에 적힌 복잡도와 STL 동작을 다시 검토하고 잘못된 수치와 표현 수정

## 주요 구현

### 호출 가능한 객체

함수 포인터와 콜백에서 시작해 멤버 함수 포인터, Functor, 람다로 확장했습니다. 호출할 동작을 외부에서 전달하는 이유와, 상태를 보관할 수 있는 Functor가 함수 포인터와 어떻게 다른지 예제로 확인했습니다. 관련 코드: [`STL.cpp`](STL.cpp)

### STL 컨테이너와 표준 알고리즘

- `find`, `find_if`, `count_if`, `all_of`, `transform`
- `remove-erase`, `unique-erase` 패턴
- `map`의 정렬된 키 탐색과 `unordered_map`의 해시 기반 탐색
- `operator[]`, `find`, `insert`, `insert_or_assign`, `emplace`의 동작 차이
- RTTI와 명시적 타입 열거를 이용한 객체 타입 확인

`unordered_map`의 삽입·조회·삭제는 평균 `O(1)`이지만 해시 충돌이 집중되는 최악의 경우 `O(N)`이 될 수 있다는 점까지 구분했습니다. 관련 코드: [`STL.cpp`](STL.cpp), [`algorithm.cpp`](algorithm.cpp)

### 직접 구현한 정렬 알고리즘

| 알고리즘 | 평균 시간 | 최악 시간 | 추가 메모리 | 안정 정렬 |
| --- | ---: | ---: | ---: | --- |
| BubbleSort | `O(N²)` | `O(N²)` | `O(1)` | 예 |
| SelectionSort | `O(N²)` | `O(N²)` | `O(1)` | 아니요 |
| HeapSort | `O(N log N)` | `O(N log N)` | `O(log N)` 호출 스택 | 아니요 |
| MergeSort | `O(N log N)` | `O(N log N)` | `O(N)` | 예 |
| QuickSort | `O(N log N)` | `O(N²)` | 평균 `O(log N)`, 최악 `O(N)` 호출 스택 | 아니요 |

표의 수치는 현재 구현의 이론 복잡도입니다. 아직 실행 시간을 직접 비교한 결과는 아니므로 성능 개선 효과를 측정값처럼 주장하지 않습니다. 관련 코드: [`algorithm.cpp`](algorithm.cpp)

### Binary Search Tree

부모·왼쪽·오른쪽 포인터를 갖는 노드를 이용해 탐색, 최솟값·최댓값, 후속 노드, 삽입, 삭제를 구현했습니다. 한 방향으로 내려가는 작업은 반복문으로, 서브트리 구조를 그대로 따라가는 작업은 재귀로 표현하며 두 방식의 차이를 기록했습니다.

현재 구현은 같은 키를 왼쪽에 삽입하지만, 중복 키를 허용할지에 대한 명시적인 정책과 전체 노드를 정리하는 소멸자는 추가 과제로 남겨두었습니다. 관련 코드: [`BinarySearchTree.h`](BinarySearchTree.h), [`BinarySearchTree.cpp`](BinarySearchTree.cpp)

### Dynamic Programming

조합 계산과 `+1`, `+2`, `+3`으로 목표 수에 도달하는 경우의 수를 재귀로 표현하고, 이미 계산한 결과를 캐시에 보관해 중복 계산을 제거했습니다. 관련 코드: [`algorithm.cpp`](algorithm.cpp)

## 직접 변경한 구현 상세

### 벡터 자체를 힙으로 만드는 HeapSort

모든 원소를 `priority_queue`에 하나씩 삽입하는 방식과 별도로, 기존 벡터의 마지막 부모부터 루트까지 `Heapify`하여 힙을 구성했습니다. 이 방식의 힙 구성은 `O(N)`, 전체 정렬은 `O(N log N)`이며 별도의 힙 컨테이너를 만들지 않습니다.

현재 `Heapify`는 재귀이므로 호출 스택 `O(log N)`을 사용합니다. 관련 코드: [`Heapify`, `HeapSort`](algorithm.cpp)

### 병합 정렬의 임시 버퍼 재사용

병합할 때마다 새로운 벡터를 생성하지 않고, 최상위 `MergeSort`에서 입력 크기만큼의 임시 벡터를 한 번 만든 뒤 모든 재귀 호출에 전달합니다. 총 보조 공간은 `O(N)`으로 같지만 반복적인 동적 할당을 피할 수 있습니다.

전역 또는 `static` 버퍼를 사용하지 않으므로 호출이 끝나면 메모리가 해제되고, 동시에 실행된 정렬끼리 버퍼를 공유하지 않습니다. 관련 코드: [`MergeSort`, `MergeSortInternal`, `MergeResult`](algorithm.cpp)

### 중복값을 고려한 QuickSort 분할

피벗과 같은 값에서는 양쪽 탐색 포인터를 멈추고, 값을 교환한 뒤 `low`와 `high`를 직접 이동합니다. 같은 값을 계속 검사하며 무한 반복하는 경우를 막고, 중복값이 많은 입력이 한쪽으로만 분할되는 현상을 줄였습니다.

다만 첫 원소를 피벗으로 선택하므로 정렬된 입력 등에서는 여전히 최악 `O(N²)`이 될 수 있습니다. 관련 코드: [`Partition`, `QuickSort`](algorithm.cpp)

### 경계값을 고려한 이진 탐색과 vector 삭제

빈 벡터에서 `size() - 1`을 계산하기 전에 반환해 unsigned 언더플로우를 막았습니다. 중간값은 `(start + end) / 2` 대신 `start + (end - start) / 2`로 계산해 덧셈 오버플로우 위험을 줄였습니다.

`vector`를 순회하며 삭제할 때는 `erase`가 반환한 다음 유효 반복자를 받고, 삭제하지 않은 경우에만 반복자를 증가시킵니다. 관련 코드: [`STL.cpp`](STL.cpp)

## 강의와의 차별화

- 빈 벡터에서 `size() - 1`을 먼저 계산해 큰 unsigned 값이 될 수 있던 조건 방어
- `vector::erase` 후 무효화된 반복자를 증가시키거나 다음 원소를 건너뛰는 순회 방식 수정
- 같은 값에서 멈추는 QuickSort 조건을 추가한 뒤 포인터 이동이 없어 무한 반복할 수 있던 문제 수정
- `unordered_map`의 삽입·조회·삭제를 항상 `O(1)`로 설명하던 내용을 평균 `O(1)`, 최악 `O(N)`으로 수정
- 포인터 반환과 RVO를 혼동했던 설명을 객체가 아닌 주소값 복사라는 내용으로 수정
- `std::unique`가 전체 중복이 아니라 인접한 중복만 제거한다는 조건 명시

4. 다른 학습 예제를 실행할 때는 해당 `#if 0` 영역을 활성화하고, 프로젝트 전체에서 `main()`이 하나만 남도록 조정합니다.
